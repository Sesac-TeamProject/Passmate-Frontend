# 폰 폭(390px) 실측 대장

> 측정: 2026-09-19 · 43경로 전수 · 목 모드
> 다음에 "폰 대응 어디까지 됐나"를 물을 때 **추측하지 말고 이 표를 본다.**
> 이 표가 생긴 이유 — 핸드오버에 코드를 확인하지 않고 적은 후보 목록이 있었고,
> 그 목록의 두 묶음(`/result` 계열 · `/me` 하위)은 **이미 끝난 상태**였다.

## 재는 방법

레포 사본을 만들어 3100에 목 모드로 띄우고, `public/harness.html` 에 390×844 iframe 을 두고
`contentDocument` 로 요소 좌표를 직접 잰다. 절차는 `HANDOVER.md` 의 "화면 확인하는 법" 과 같다.

판정은 두 숫자다.

- `documentElement.scrollWidth` — 390 을 넘으면 페이지가 옆으로 밀린다
- 뷰포트(391px)를 벗어난 요소 개수

**가로 스크롤 레일 안의 요소는 세지 않는다.** 조상에 `overflow-x: auto|scroll` 이 있으면
의도된 레일이다(랜딩·홈 캐러셀). 이걸 빼지 않으면 멀쩡한 화면이 "12곳 넘침" 으로 잡힌다.

```js
// 레일 안인지 판정 — 이 한 줄이 오탐을 없앤다
for (var p = el.parentElement; p && p !== de; p = p.parentElement) {
  var ox = getComputedStyle(p).overflowX;
  if (ox === "auto" || ox === "scroll") return; // 세지 않는다
}
```

## 재면서 걸린 함정 (다음에 또 걸린다)

- **상태 리다이렉트로 같은 화면을 여러 번 잰다.** 목의 방이 `WAITING` 이라
  `/live` · `/result` · `/final` 이 전부 `/lobby` 로 갔다. 네 화면이 똑같이 550px 로 나와
  "같은 셸이라 당연하다" 고 읽었는데 **대기실을 네 번 잰 것**이었다.
  → **착지 URL(`location.pathname`)을 매번 확인한다.** 숫자만 보면 안 된다.
- 진행 화면은 목의 상태 머신을 UI 로 밀어야 나온다: 대기실 `시험 시작` → `/live`,
  `정답 공개` → `/result`, `다음 문항` 을 끝까지 → `세션 종료` → `/final`.
  파일을 고치면 dev 서버가 다시 뜨면서 목 상태가 `WAITING` 으로 돌아간다.
- **데이터가 오기 전에 재면 로딩 화면을 잰다.** 본문 텍스트를 같이 받아 확인한다.
  목이라도 2.6초로는 모자란 화면이 있다(6~7초로 준다).
- **브라우저 JS 는 45초 제한.** 문항 8개를 넘기며 재려 하면 넘는다 — 진행과 측정을 나눈다.
- `/me/withdraw` 의 `탈퇴하기` 는 **확인 다이얼로그가 없다.** 체크박스만 누르면 바로 실행된다.
  자동화로 화면을 훑을 때 무심코 누르면 목 탈퇴가 돌고 랜딩으로 튕긴다.
