## 2. A. 화면 자체가 없음 — 신규 프레임 요청

### A-1. 학생 결과·리포트 (웹) — `/result/[sessionId]` · **P2** (US5·US4·US7·US12·US8)

가장 큰 구멍이다. 세션이 끝나면 학생이 보는 화면인데 웹 시안이 없다. 앱(KMP)에는 `SessionResultResponse`·`LearningReportResponse` 기준으로 화면이 있으니 **앱 시안을 데스크톱 폭으로 옮기는 작업**에 가깝다.

들어가야 할 것 (FR 근거):

- 내 점수·최종 순위, 전체 참가자 수 (FR-026)
- 문제별 카드: 정오, 내 답, 정답·해설, 획득 점수(속도 보너스 표기) (FR-030)
- 서술형 문항: **AI 피드백 3상태** — 분석 중(대기) / 완료(핵심 포함 여부·부족한 부분·개선 방향) / 분석 불가 안내 (FR-027·029)
- **선생님 첨삭**을 AI 피드백과 구분해 표시, 보정된 최종 점수 (FR-035)
- 취약 주제(개념) 요약 (FR-030)
- **별점 1~5 + 태그 5종 + 선택 코멘트** 입력 — 계약 `POST /rooms/{roomId}/ratings {stars, tags[], comment?}`, 태그는 `CLEAR_EXPLANATION`(설명이 명확해요)·`GOOD_DIFFICULTY`(난이도 적절)·`GOOD_PACING`(진행 속도 좋아요)·`HELPFUL_HINTS`(힌트가 도움됐어요)·`GOOD_QUALITY`(문제 퀄리티) 고정. 제출 후 잠금, 이미 평가함(409), **평가 기간 24h 경과**(410) 상태, "평가 없이 나가기" (FR-042~043)
- **게스트 전용 CTA** "가입하고 기록 저장하기" + 보관 기한 7일 안내 (FR-036)
- 리포트 내보내기 버튼 (FR-063, `GET /participations/{id}/report/export`)
- 회원이면 "마이페이지 › 참여한 방에 저장됐어요" 안내 (FR-032)
- 호스트·문제 **신고** 진입(→ A-8), 호스트 이름 → 공개 프로필(→ A-7)

### A-2. 학생 웹 대기실 — P-Web 대기 상태 · **P1** (US2)

`/join`(C-03)에서 입장한 뒤 세션 시작 전까지 학생이 보는 화면. P-Web 프레임(`nwR8C`)에는 풀이 상태만 있고 메모("앱과 동일한 컴포넌트·상태 — 반응형으로 폭만 조정")만 남아 있다. 앱 시안이 있으면 그것으로 갈음해도 되지만, **웹 폭에서의 배치 1장**은 필요하다.

- 방 제목·호스트(등급·별점, FR-044·048)·PIN, 참가자 목록 실시간 갱신 (FR-006)
- 회원이면 "풀이 기록이 계정에 연동돼요" 배지 (US2-2)
- 유료 방이면 결제 완료 표시
- "선생님이 시작하면 자동으로 넘어가요" 안내, 연결 상태 표시

### A-3. 호스트 최종 결과 (프로젝터) · **P1** (US3, FR-026)

W-06(`uiWx4`)은 **문항별** 결과다. 마지막 문항 뒤 "최종 결과와 리포트가 열려요" 문구만 있고 최종 화면이 없다. 코드 `result-page.tsx`도 같은 문구로 끝난다.

- 최종 랭킹(포디움 1~3위 + 전체 목록), 전체 정답률, 세션 소요 시간
- 서술형이 있으면 "AI 분석 n건 진행 중 — 리포트에서 확정돼요" 상태
- 버튼: 리포트 보기(W-07) · 방 닫기 · (선택) 같은 세트로 새 방

### A-4. 첨삭 입력 — W-07 확장 또는 W-07-1 · **P3** (US7, FR-034~035, T071)

W-07 방 리포트(`xu88g`)는 서술형 AI 분석을 **읽는** 화면이다. 코드 `review-page.tsx`에도 코멘트·점수 보정·개선사항 **입력**이 없다.

- 학생별 답변 목록 → 답변 상세 패널: AI 피드백(읽기) + 첨삭 폼(코멘트·개선사항·보정 점수) + 저장/저장됨 상태
- 첨삭 완료 표시(학생 n명 중 m명), 첨삭 후 최종 점수 우선 규칙 안내
- 문항별 음성 힌트 사용 이력 표기 (FR-041)

### A-5. 공개 방 목록 — `/rooms` · **P4** (US14 FR-054, US16)

routes에 등록돼 있고 코드는 자리표시자. 앱에는 `PublicRoomDto` 기준 `RoomListScreen`이 있다.

- 카드: 방 제목·주제·호스트(등급·별점)·참가비/무료·정원·시작 예정 — W-01 인기 방 카드 재사용 가능
- **Lv.4+ 호스트 방 상단 섹션**, **브랜디드 퀴즈 배지** (FR-054·059)
- 필터(무료/유료/주제), 빈 상태, 로그인 없이 볼 수 있음 → 유료 방 클릭 시 로그인 유도

### A-6. 로그인 콜백 처리 중 · 실패 — `/auth/callback` · **P1** (T019)

Google 로그인 후 되돌아오는 1~2초 화면과 실패 상태. 작지만 없으면 빈 화면이 뜬다.

- 로딩("로그인 처리 중…") / 실패("로그인에 실패했어요" + 다시 시도·홈으로) / 세션 만료로 재로그인 안내(401)

### A-7. 호스트 공개 프로필 · **P3~P4** (FR-044·048, 계약 `GET /users/{userId}/profile`)

앱에는 있고 웹에는 없다. 공개 방 목록(A-5)·결제 화면(W-11)·대기실의 호스트 이름을 누르면 열리는 화면.

- 닉네임·소개·등급 엠블럼·평균 별점·평가 수·방 운영 횟수·누적 학생 수
- 획득 뱃지(8종: 첫 방·방 10회·학생 100명·별점 4.5·평가 50건·30일 연속·첫 유료 방·AI 세트 50개 — `lMoA1` v5 뱃지 재사용)
- 이 호스트의 공개 방 목록(A-5 카드 재사용), 신고(A-8) 진입
- 모달/사이드 패널 1장이면 충분

### A-8. 신고 다이얼로그 · **P3** (계약 `POST /reports`, 관리자 A-04가 소비)

관리자 A-04 신고 관리는 있는데 **신고를 넣는 쪽 UI가 웹에 없다**. 사유 6종은 서버 고정값: `NICKNAME`(부적절 닉네임)·`QUESTION_ERROR`(문제 오류)·`PAID_ROOM`(유료 방 문제)·`OPERATION`(운영)·`SPAM`(도배)·`DIFFICULTY`(난이도).

- 대상(호스트/문제/참가자) 표시 → 사유 라디오 6종 → 상세(선택) → 접수 완료
- 진입점: 결과 화면(A-1) 호스트·문항, 호스트 대기실/진행(W-04·05) 참가자 메뉴, 호스트 프로필(A-7)
- 게스트도 익명 신고 가능
